# Продуктовая аналитика магазина косметики

[Репозиторий проекта](https://github.com/7drezz/cosmetics-product-analytics)

Семестровый проект PA-S1, индивидуальный трек Б. Исследование истории событий магазина косметики REES46 за октябрь 2019 — февраль 2020: 20 692 840 событий, 1 639 358 пользователей.

## Вопрос и гипотеза

Как повысить ранние покупки и сохранить возврат пользователей? Предлагается показать стоимость и условия доставки в корзине до оформления. Это гипотеза для будущего A/B-теста: история событий не доказывает, что доставка объясняет поведение пользователей.

Ноутбук содержит девять разделов задания: продукт, данные, определения, метрики, трекинг, расчёты, этика, цели и воспроизводимость. Код, таблицы и графики сохранены вместе с результатами выполнения.

## Основные результаты

| Метрика | Определение | Результат |
|---|---|---:|
| Покупатели за неделю (WBU) | Уникальные пользователи с `purchase`, среднее по полным календарным неделям | 6 910,2 |
| Конверсия в покупку за первые 7 дней (CR7) | Покупка в дни 0–6 / вся зрелая когорта | 4,77% |
| Удержание на четвёртой неделе (R4) | Любое событие в дни 28–34 / вся зрелая когорта | 3,38% |
| Стоимость покупочных событий за 30 дней на пользователя (V30) | Неотрицательный `purchase.price` в дни 0–29 / все пользователи зрелых когорт | 2,6315 |

Когорты недельные, время — UTC. Первое событие обозначает начало наблюдения, а не регистрацию. Показатели имеют собственные зрелые выборки; общий baseline целей выделен в ноутбуке отдельно. Незрелые окна не заменяются нулями.

Покупка в дни 7–96 — предварительный кандидат для анализа всех назначенных в эксперимент пользователей (ITT). Исторические 3,95% — прокси, не экспериментальный baseline и не защитный порог.

## Экономика и ограничения

Для 1 170 587 пользователей 16 полных зрелых когорт заданы ровно два синтетических поля: условный канал и расход на пользователя. Три канала имеют целевые доли 50/30/20 и расходы 1/2/3. Назначение воспроизводится по `user_id` с seed 20261101 и не зависит от покупок и активности. Названия каналов и фактические доли приведены в ноутбуке.

`CAC канала = синтетические расходы канала / назначенные пользователи`; общий CAC использует всю выбранную популяцию. `LTV30_s = сценарная ставка маржи × V30`; `LTV30_s/CAC = LTV30_s / общий синтетический CAC`.

Общий синтетический CAC — **1,7008**. При сценарной марже 25/50/75% отношение LTV30/CAC составляет **0,3868 / 0,7736 / 1,1604**. Денежные величины выражены в единицах исходного `price`; валюта не подтверждена. `purchase.price` — стоимость записанных событий, а не подтверждённые оплаты. Реальные расходы, каналы и маржа отсутствуют; фактическая экономика по каналам закрыта частично. Окупаемость магазина и эффективность каналов из этих сценариев не следуют.

## Подготовка данных

Источник: [Kaggle, eCommerce Events History in Cosmetics Shop](https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop), [REES46](https://rees46.com/en/datasets).

Скачайте исходный архив и поместите его в `data/raw/cosmetics.zip`. Он должен содержать `2019-Oct.csv`, `2019-Nov.csv`, `2019-Dec.csv`, `2020-Jan.csv`, `2020-Feb.csv`. Ноутбук извлечёт отсутствующие CSV и сверит файлы с манифестом. При другом снимке проверка остановит запуск; не обходите её заменой хэшей без проверки данных.

CSV занимают около 2,43 ГБ; дополнительно нужно место под архив, промежуточную базу и временные файлы. DuckDB ограничен 3 ГБ памяти, весь набор не загружается в pandas. Готовый кеш не требуется. На Kaggle указано «Data files © Original Authors». Отдельная открытая лицензия и явное разрешение на перепубликацию не указаны, поэтому архив и CSV в комплект не включены. Официальный номер версии не подтверждён.

## Запуск

Есть два способа: через интерфейс JupyterLab или одной командой без интерфейса. Сначала подготовьте данные по инструкции выше.

### Способ 1. Через JupyterLab

Нужен Python 3.11. Откройте PowerShell в папке проекта и выполните:

```powershell
py -3.11 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m jupyterlab
```

Откройте `cosmetics-product-analytics.ipynb`, выберите ядро созданного окружения и выполните **Restart Kernel and Run All Cells**. Рабочая папка ядра должна быть корнем проекта. Для чтения сохранённых результатов повторный запуск не нужен.

### Способ 2. Одной командой без интерфейса Jupyter

После создания окружения и установки зависимостей из первого способа выполните:

```powershell
./.venv/Scripts/python.exe tools/execute_notebook.py
```

Скрипт сохраняет выполненный ноутбук и `outputs/execution_report.json`. Расчёт создаёт таблицы в `outputs/tables/`, графики в `outputs/figures/` и сводку `outputs/results_summary.json`. Повторный запуск перезаписывает производные результаты, сохраняя исходные CSV.

## Что проверено

Все ячейки выполнены в свежем ядре без готового кеша. Проверены целостность и схема входных файлов, преобразования ключей и дат, сохранение строк, зрелость окон, знаменатели метрик, популяция экономики и воспроизводимость синтетических полей. Контрольная сверка подтвердила аналитические результаты. Это подтверждает реализацию расчётов, но не реалистичность синтетических допущений и не эффект будущего эксперимента.
